# 二叉搜索树 (Binary Search Tree / BST) 刷题笔记

> BST = 二叉树 + 一条铁律。这条铁律给了两个方法(比大小走一边 / 中序有序),
> 大多数BST题就是这两个方法的排列组合。
> **本笔记只记思路和判断法,不留完整代码——复习时靠这些提示自己重新推出代码。**

---

## 一、三个容易混的名词,先分清

| 名词 | 英文 | 是什么 | 例题 |
|---|---|---|---|
| 二叉树 | Binary **Tree** | 数据结构:每节点≤2个孩子,值无规则 | 104,226,102 |
| 二叉搜索树 | Binary **Search** Tree(BST) | 二叉树+左小右大规则 | 700,98 |
| 二分查找 | Binary Search | **算法**,有序数组上砍半找 | 704 |

⚠️ 读题看到 "binary **search** tree"/"BST" 要条件反射想两个方法,别当普通binary tree做(否则O(log n)题写成O(n),面试被追问"BST性质用了吗")。

## 二、BST精确定义(比"看起来"更严格)

> **对每个节点:整棵左子树的所有值 < 我 < 整棵右子树的所有值**

关键词是**"整棵"**和**"每个节点都要满足"**——不是"左孩子<我<右孩子"(那只是局部)。

**反例(局部对、整体错)**:根5,右孩子8,8的左孩子2 → 2<8局部对,但2在5的右子树里该>5,2<5,整体错。
**我最早的思路误区**:以为"比孩子如何"就够了,漏了"要看整棵子树、约束跨越多层祖先"这件事——这正是98需要上下界的原因。

## 三、两个方法

**方法1:比大小,只走一边**(O(h)≈O(log n))
```python
if val < node.val:   往左   # 小的在左
elif val > node.val: 往右   # 大的在右
else:                就是它
```
用于:搜索(700)、插入(701)、删除(450)、LCA(235)、最接近值(270)、修剪(669)、拆分(776)

**方法2:中序遍历 = 从小到大有序**
BST"左<我<右",中序"左→我→右"正好按大小走 → 吐出升序。
```python
def dfs(node):
    if not node: return
    dfs(node.left)
    处理node.val         # 具体处理方式看题:比prev、计数、存array...
    dfs(node.right)
```
用于:验证BST(98)、第k小(230)、最小差(530)、众数(501)

**拿到BST题先问**:查找/插入/删除/修剪/拆分某个值 → 方法1;验证有序/第k小/最接近/统计 → 方法2。

## 四、核心连线:BST方法1 = 二叉树上的二分查找

BST方法1 和 704二分**本质是同一个东西**——同一个"比大小、砍一半、走一边"的思想,两种数据结构上的化身。

| | 二分(数组) | BST方法1(树) |
|---|---|---|
| 靠什么砍半 | 数组有序 | 左<我<右 |
| "中间"是谁 | `nums[mid]` | 当前 `node` |
| 小了往哪 | 左半 | 左孩子 |
| 大了往哪 | 右半 | 右孩子 |

**BST = 把有序数组组织成了树形**:数组 `[1,3,5,8,10,14]` 二分跳中点8 ≈ BST根是8、左子树是左半、右子树是右半。

**整张记忆网**:对撞双指针(挪1格)→ 有序能砍半 → 二分查找(数组砍半)→ **BST方法1(树上砍半)**

### 递归 vs 循环:什么时候不用递归

**判据:走完一个分支还要回头走另一个吗?**
- 要回头/分叉(左右都处理)→ 递归:98(中序)/230
- 只走一条路,永不回头(单路下探)→ **循环够了**:700/701/235(=树上二分,像704那样while)

方法2(中序)还得递归(要遍历全树)。能循环的循环更好(不占递归栈);面试写循环是加分项。

## 五、方法1实战

- **700 搜索**:最纯形态,一个while循环,比大小走一边。
- **701 插入**:走到空位(None)时,**造一个新节点交上去**——这就是插入发生的瞬间。父亲 `node.left = 递归结果` **接住重挂**。对比700(底返回None="没找到")vs 701(底返回新节点="给你造一个")——一行之差,只读变改写。
- **235 BST的LCA**(比普通树236简单得多):p、q都比我小→往左;都比我大→往右;一左一右(或撞上其一)→我就是LCA。p、q第一次"分道扬镳"的节点就是答案——纯循环,不用递归。

## 六、方法2实战(中序,边走边处理)

### 98 验证BST —— 两种解法都要会

**解法A(中序检查递增)**:中序走一遍,记住"上一个值",每个新值必须严格大于上一个。
**解法B(上下界,推荐先学这个)**:每个节点带一个允许范围(low, high),往左走时上界收紧成我、往右走时下界收紧成我。

**为什么必须传low/high(这道题的灵魂)**:一个节点光看自己和孩子,判断不了合不合法——它看不到祖先定的规矩(比如"我在5的右子树里,必须>5",这约束来自祖先)。**low/high就是把"从根到我,所有祖先定的规矩"打包传下来验票**。两个都要传:一个节点可能同时被"要>某祖先"和"要<某祖先"两头夹。这个"往下传约束、越传越紧"和112传remaining同构。

### 230 第k小的元素
思路1(推荐先用):中序存进array,取下标 `k-1`(第k小对应下标k-1,别漏减1)。
思路2(进阶,更省空间):边走边计数,数到第k个立刻停,不用存整个array。

### 530 二叉搜索树的最小绝对差
中序有序 → **最小差一定出现在相邻两数之间**,不用两两比较。跨层要记"上一个值"这种**会被内部函数修改**的变量,普通局部变量会报错(Python把内部函数里的赋值当成新建局部变量)——要用 `nonlocal 变量名`(嵌套函数通用)或 `self.变量名`(class方法里更常用)。

### 501 二叉搜索树中的众数(可能并列最多)
不用先存array,直接在dfs里维护一个"值→次数"的字典,边走边计数。`dict.get(key, 默认值)` 是关键词组:取不到key时返回默认值,不报错,一行处理"第一次见"和"再次见"两种情况。

### 270 最接近目标值
方法1(比大小走一边)+ 边走边更新"最接近"记录。
**易错点**:如果用严格小于判断"要不要更新",会漏掉"差距一样"的情况,可能卡在错误的初始值上出不来——平局时要额外规定"选更小的那个"当决胜规则。

## 七、改结构类:接住重挂(BST的核心操作模式)

**凡是会改变树结构的操作(删除/插入/修剪/拆分),必须用分治:dfs返回"处理好的子树根",父亲用 `root.left = dfs(root.left)` 接住重挂。**

**为什么遍历做不到**:遍历没有向上交付的通道,深处对node的重新赋值只改了局部变量,父亲的指针没跟着动,"接不上"。
**分治能做到**:父亲拿返回值覆盖自己的指针,一次赋值完成接线。

### 450 删除BST节点(全场最难,三种情况)

先用大小关系单路找到key。找到后:
- **只有一个/没有孩子**:唯一存在的那个孩子(或None)直接顶替我的位置。
- **两个孩子都有**(最难):谁都不能直接顶替(顶替谁,另一片子树就丢了)。需要找一个"完美嵌入"的替身——**右子树里最小的那个值**(唯一能同时满足"比左子树全大、比右子树剩余全小")。做法:不搬节点(牵连太多连线),**只搬值**——把替身的值复制给当前node,树形状不变;搬完后原地留了个重复值,**递归调用同一个函数**去右子树把那个重复值删掉(这次递归对象必然没有左孩子,自然落入简单情况,不会无限递归)。
- 镜像替身("左子树里最大的")同样成立——这是LC提示"另一个可接受答案"的来源。

### 669 修剪二叉搜索树(450的简化版,没有找替身这一步)
每个节点先问自己:太小(< low)→ 我和整个左子树全部作废,唯一有救的是右子树,直接把右子树递归修剪的结果**返回**;太大(> high)→ 对称,返回左子树的结果;在范围内 → 我合法,但孩子未必合法,递归修剪两边+接住重挂。
**最容易错的点**:判断"我不合法"的分支,必须**直接return**递归结果,不能赋值给node后继续往下走——赋值不返回,代码会用一个已经不对的node继续做"合法节点该做的事",逻辑就乱了。**"这里该结束"永远用return,不是赋值。**

### 776 二叉搜索树拆分(拆成两棵树,返回两个根)
每个节点判断自己归哪棵树(≤target归小树,>target归大树)。分治要**返回一对**(小树的这部分,大树的这部分)——用tuple。归小树的节点,先把自己的右子树递归拆开,拿到的"小的那部分"接在自己右边,"大的那部分"直接往上交给父亲去接(对称地,归大树的节点处理左子树)。
**核心画面**:某个节点被挖去当小树的根后,它原来的位置在父亲那边空出来,由"从它这边拆出来、归大树的那部分"补上。
**`a, b = dfs(...)` 是拆包一个tuple,不是调用两次**——dfs只跑一次,返回值是一个打包了两个东西的结果,用逗号一次性拆开分装两个变量。
**为什么这题必须分治,不能用res收集**:答案是"两棵接好线的树",不是一堆散落的值——construct/接线是分治回程拼答案的活,res收集不出"结构"。

## 八、⚠️ 易错点合集

1. 判断BST合法性,别只看直接孩子——要看整棵子树,跨祖先的约束用low/high传递(98)。
2. 改结构的题,"该结束"永远用return,不是赋值(669踩过)。
3. 平局/相等的情况要单独想清楚(270):严格小于会漏掉"一样近"的更新机会。
4. `a, b = dfs(...)` 是拆包一个tuple,不是调用两次。
5. 跨层要修改(不只是读)的变量,内部函数里直接赋值会报错——用 `nonlocal` 或 `self.`。
6. BST方法1题,能用循环就用循环(判据:走完一边还要不要回头走另一边)。
7. `dict.get(key, 默认值)` 处理"key可能不存在"的取值,不会报错。

## 词组/工具速查(遇到时知道该用什么,不用记代码)

| 场景 | 该用的工具 |
|---|---|
| BST走一边 | 三元表达式选左/右孩子 |
| 上下界往下传 | 递归多传两个参数,左右各收紧一个 |
| 需要返回多样东西 | tuple,`a, b = dfs(...)` 拆包接收 |
| 跨层要修改的变量 | `nonlocal` 或 `self.` |
| 计数,容错取值 | `dict.get(key, 0)` 或 `Counter` |
| 平局时选更小的 | `min(a, b, key=lambda x: (差距, x))` |
| BST找最小值 | 一路向左走到底 |
